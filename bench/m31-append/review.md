# Public M31 append: design review

Status: consolidated native/Cairo and authenticated-fixture source review complete, 2026-09-21. This review does not approve a production migration or a private proof construction. All inputs are synthetic and public; earlier archives are immutable.

## Approved bridge

Use the reviewed M31 permutation AIR with ordinary Blake2s, verify its proof and the complete append statement inside a Cairo program, then prove that execution through the unchanged fixed Cairo/PROOF1 pipeline. The isolated Cairo verifier may reuse `verifier_core`, software QM31, and the constraint framework from S-two Cairo commit `16700cc9a03fe43a6801ca87b4ff685aeb26339d`, already archived in `bench/direct-air/cairo/vendor`. Its generic `Air<T>` interface supports this relation. A new adapter must mirror the existing 1172-column quadratic permutation evaluator and its four interaction columns exactly.

This route does not reinterpret an ordinary-Blake2s proof as a reduced-Blake2sM31 circuit proof. The incompatibility recorded in `bench/client-privacy-feasibility/integration-plan.md` remains; the accepted fixed outer circuit instead verifies the Cairo execution that verified the ordinary inner proof. No new masking, private topology, field arithmetic, FRI equations, or proof parameters are proposed.

The Cairo program must execute the structural checks below and independently derive the lookup boundary. A host-generated statement hash, claimed boundary, or successful native validation is not a substitute. Compilation and native inner-proof acceptance alone do not establish this bridge.

## Append relation

The batch length is restricted to `n = 1` or `n = 2`. The public statement binds the version, chain, pool, old root/count, exact ordered canonical felt252 commitments, and new root/count. Counts use checked integer arithmetic: `old_count + n <= 2^32`, and `new_count = old_count + n`. Each appended index is exactly `old_count + i`; no prover-selected index is accepted.

For each append, validate two depth-32 paths using the **same siblings and index bits**. The old path begins at the fixed reviewed empty-leaf digest; the new path begins at the domain-separated hash of that append's commitment. Each level checks left/right order, level domain, both sponge permutation requests, absorption, capacity, padding, and extracted digest. The old endpoint equals the current intermediate root; the new endpoint becomes the next intermediate root. The last endpoint equals the declared new root. The local pool initializes at the trusted empty root/count zero and permits only this transition, so its state history supplies the occupied-prefix invariant. This is not an assertion that an arbitrary imported old root has a valid append history.

Reuse the frozen M31 construction without modification: Plonky3 `00fe0a985b398d3ef1f10d69543ca2b8f9f236da`, width24 Poseidon2, RF8/RP22, x^5, exact fixed constants/matrices, rate15/capacity9/output9 Pad10 sponge, and the reviewed leaf/node/empty domains. Canonical felt252 commitments encode as nine little-endian 28-bit limbs. Digest words are strictly below `2^31-1`; packing remains eight 31-bit words in the low felt and the ninth word in the high felt. Reject forbidden digit `P`, excess high bits, noncanonical felt encodings, or reduction/truncation aliases. If Cairo decodes limbs rather than deriving them from an existing felt, enforce the integer felt-prime bound before reconstruction; a field equality alone is insufficient.

Each append supplies 129 real permutation requests: one leaf request and 128 requests for the old/new node paths. Thus `n=1/2` gives 129/258 requests, deterministically padded by copies of the first request to 256/512 rows. Preserve duplicates and every padding occurrence in both the trace and public boundary. These two exact shapes are verifier-derived; arbitrary topology or log sizes are forbidden.

## Transcript, AIR and PCS invariants

Approve the newly versioned fixed-word append encoding proposed by both specialists. It replaces the earlier benchmark's JSON encoding for this new protocol only; old proof-byte compatibility is not claimed:

1. Words `[0x544d5041, 1, n]`, chain and pool as nine LE28 limbs each, old/new counts as two LE28 limbs each, old/new roots as nine M31 words each, then ordered commitments as nine LE28 limbs each.
2. For each append in order, its 32 sibling digests followed by its 129 ordered permutation requests, each as 24 input words then 24 output words. Every word is canonical M31; lengths are derived and checked.
3. Start the ordinary Blake2s channel at zero. Mix the word count with `mix_u64`, then one `mix_felts` of successive four-word QM31 coordinates, zero-padding only the final group. The explicit word count makes this last padding unambiguous. Mix the exact PCS configuration, trusted empty preprocessing root, derived trace log, and base commitment, followed by the unchanged interaction and STARK transcript sequence.

Retain PoW27, blowup log3, 23 queries, fold step4, last-layer degree log0, and interaction PoW24. Trace logs are 8/9 and lifting logs 11/12. Cairo must compare the entire supplied configuration against this derived tuple; generic verification's minimum-security check alone does not establish configuration equality. The inherited `27 + 3*23 = 96` convenience metric is not an exact soundness theorem. The hash's 128-bit design target is separate, and the outer public binding also uses the existing felt252 Poseidon hash.

The adapter must preserve constraint order and Horner accumulation, initial external matrix, every materialized round state, x²/x⁴ checks, final input/output relation tuple and relation ID. Consume exactly 1172 one-point base masks and four previous/current interaction masks, with no unused or extra masks. Its one negative lookup term per row uses the same centered running-sum equation and claimed-sum normalization as Rust. Derive the positive public boundary from all padded requests and require its sum with the AIR claimed sum to be zero. The aggregate occurrence count is at most 1024, below the characteristic. Return the combined constraint **numerator** to Cairo's generic verifier, which applies the trace vanishing denominator; do not divide twice. All OOD, FRI, PoW and Merkle checks remain active.

### Empty preprocessing compatibility

The reviewed native prover commits zero preprocessing columns as a height-zero tree with the canonical nonzero empty hash. Its client verifier already normalizes this exact case and rejects extra empty-tree samples, queried values and witnesses.

The June25 Cairo `CommitmentSchemeVerifier.commit` otherwise assigns the empty tree height equal to the blowup log. Constructing that first verifier entry at height zero, with the **same root mixing**, is necessary. Independent source inspection found a second mismatch: Cairo's Merkle verifier then pops an empty query queue, whereas pinned Rust returns successfully at height zero.

Approve one isolated, explicitly archived compatibility branch: only for height zero, require zero columns, empty query positions, queried values and hash witness, and root equality to the canonical empty-leaf hash, then return. Keep the bridge's empty sampled-values guard and trusted-root comparison. All nonempty verification paths must remain unchanged. This normalizes the exact honest empty commitment; it does not permit skipping a populated tree. Require a regression demonstrating the unadapted failure, adapted success, identical channel/configuration, and rejection of each extra empty-opening field and a changed root.

## Public output and local acceptance

Approve the transition preimage:

`[M31_APPEND_V1, chain, pool, old_root_low, old_root_high, old_count, n, commitments..., new_root_low, new_root_high, new_count]`.

Its existing felt252 `poseidon_hash_span` binds all transition fields. The proved account emits exactly the approved schema `[class_hash] + public8`, where `public8` is `[M31_APPEND_V1, chain, pool, old_low, old_high, old_count, transition_hash, n]`. The compiled account/verifier fixes the hash construction and format version. The proof's program, account, class and message authority must come from trusted application configuration, never unchecked proof metadata.

The statement account can be stateless and generic: it checks the actual execution chain and a canonical nonzero pool address. The receiving pool supplies the remaining authority by requiring its own address and the exact approved statement account/class/program. An account-to-pool storage pin is unnecessary.

The local pool reconstructs the transition preimage from the submitted canonical header and exact authorized commitments in order. The runtime must establish proof validity before exposing `proof_facts`; the pool checks intended program/message identity, chain/pool/version, current old root/count, valid batch length, exact new count, and all public facts before writing root, count or authorization state. A changed new root/count is covered by the transition hash even though it is not repeated directly in `public8`. Rejecting an update must leave all these state fields unchanged. No M31 permutation execution is required in the acceptance contract.

Real native PROOF1 verification, execution of a contract using those verified facts, and a local node accepting an attached PROOF1 are separate milestones. Injected test facts do not demonstrate the last one. If the pinned service needs a synthetic authenticated RPC base state, it must provide self-consistent canonical class/CASM hashes, contract/storage/class Patricia paths, address/nonce/storage leaves, block/header and global roots verified by the unchanged prover. Pin the base-state and program authority outside untrusted replies; retain all authentication checks. Such a fixture is a local trust anchor, not evidence of network finality.

### RPC encoding and trust boundaries

The reviewed transport preserves positional contract leaves and storage proofs. ### Duplicate query export correction

A later valid native branch proof reached the export-only `q == n_queries` assertion. This is an exporter assumption, not a proof-parameter failure. Pinned Rust `draw_queries` draws exactly 23 masked words, then `Queries::new` sorts and deduplicates using a `BTreeSet`. Cairo `Queries.generate` increments its counter on **every** insertion, including a duplicate, then squashes/sorts the dictionary. Both therefore derive the same unique positions from 23 draws, and legitimate opening cardinality can be smaller than23.

Approve only changing the serializer guard to `0 < q <= configured n_queries`, retaining identical q across every one of the 1172 base, four interaction and eight composition columns and the same row transposition. The native and Cairo verifiers independently derive the exact positions and enforce opening consumption; the exporter does not choose cardinality. Do not redraw until unique, pad duplicate openings, change configuration or regenerate proof data. Independently reviewed the resulting `wire.rs` diff against frozen-v1, SHA256 `05b18c4580b8712c5c486e66eaa04c2e82798b4196b22e4b6f79a2d47b6cf460`: only the guard, helper extraction and two focused test functions changed.
