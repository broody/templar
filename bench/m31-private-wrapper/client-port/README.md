# Private membership to PROOF2, end to end

2026-09-23. **A real client-private membership proof is now verified on the server
and wrapped as a genuine PROOF2.** The retained TMPZK002 Blake proof was verified
by circuit A (the complete client verifier as one server circuit). The circuit-A
proof was verified in Cairo by an account executing in the pinned virtual OS, and
that execution was proven with Starknet v0.14.4's large-proof path. The V2
verifier accepts it, and three altered inputs are rejected.

The private witness never leaves the client. The server sees only the public
statement and the hiding client proof. This is membership only, not a payment.
The virtual-OS state is a synthetic local fixture (block 100), so no network
submission was made. Circuit A has not had independent math review. See
[PLAN.md](PLAN.md) for the review items.

> **Current stack:** since 2026-09-23 the pipeline builds on `starkware-libs/proving@5a7c5ed`
> with the unmodified upstream Cairo verifier. See [results/proving-stack/](results/proving-stack/README.md).
> The numbers below are from the earlier pre-monorepo pins.

## Pipeline (TMPZK002 route)

| Stage | Where | Time | Peak memory | Evidence |
| --- | --- | ---: | ---: | --- |
| Client proof (TMPZK002 Blake) | client | ~1.0 s | ~53 MiB native / 63 MiB WASM | [client results](../../m31-private-blake/README.md) |
| Circuit A (log23): verify client proof | server | 69.6 s | 39.7 GiB | `results/circuit-a/` |
| Virtual-OS execution of the bridge account (6.88M steps) | server | ~13 s | <16 GiB | `results/os-capture/` |
| PROOF2 large path (log25 leaf) | server | 141 s | 62.6 GiB | `results/proof2/` |

Server stages run sequentially on four pinned workers, zero swap. The PROOF2 is
254,546 bytes (gateway cap 480,000) and verifies in 0.10 s. The first run had
circuit A at log25 (144 s / 92.2 GiB); it is kept in `results/log25-baseline/`.
The drop to log23 came from building leaf and node messages word by word
(`src/aligned.rs`) instead of splitting every value and digest into range-checked
bytes. Arithmetic rows fell from 17.9M to 6.3M, TripleXor from 3.19M to 0.86M and
Eq from 3.02M to 0.27M; BlakeG is unchanged at 6.35M. The server peak is now the
PROOF2 stage. Its fixed floor is about 42 GiB even for a 276k-step transaction.

## What each layer checks

- **Circuit A** (`src/`): the whole `proof::verify`. That covers transcript and
  coins, every Merkle opening, OOD sampling and the 1,273-constraint composition
  identity (compiled from the client's own `air::constraints`), the DEEP batch,
  ten FRI folds and the final constant. It accepts all six retained proofs with
  one topology. Its outputs are `Blake2s(x)` and the root. Tests: `tests/` (17).
- **Bridge account** (`cairo/`): deserializes exactly one circuit-A proof with no
  trailing data. It verifies it against the pinned root and config (generated by
  the existing trusted generator from `results/circuit-a/trusted-config.json`) and
  emits `(class, 'TMPZK002_MEMBERSHIP_V1', chain, Blake2s(x), root)`. The account
  compiles to 79,687 felts, under the 81,920 declared-class limit.
- **Statement.** `x = "TMPZK002" ‖ client-circuit digest ‖ {"chain","pool","root"}`.
  The consuming pool must rebuild `x` from its own chain, address and the root
  (`templar_membership_bridge::statement_bytes`) and compare digests. That check
  lives in the pool because adding it to the account exceeded the class size limit.
  The bridge executable runs the full check. `results/bridge-validation/` shows the
  real proof accepted in 4.93M steps with output exactly `(chain, pool, root)`, and
  rejections for altered digest output, root output, pool, chain, trailing and
  truncated data.
- **OS capture** checks the single emitted message exactly against an independent
  Python computation of `Blake2s(x)`. The PROOF2 input PIE hash (`4d12ae…`) equals
  the checked capture's.
