# Implementation status

<div className="guide-eyebrow">Snapshot / 24 September 2026</div>

Templar [proves](/architecture/proving) each spend as a compact client proof that a wrapping server turns into a Starknet large proof. This runs end to end locally with real proofs for ordinary spends, open notes and policy notes, and reaches Sepolia up to the gateway, which does not accept large-proof transactions yet.

Everything here is an unaudited, experimental construction with synthetic tokens. Key derivation, address and backup formats, viewing exports and delivery representations require independent review before production formats are frozen. The primary packages and a production wallet are not yet integrated.

## Ordinary spends (R0)

The wallet proves an R0 spend from the pool's own events; a wrapping server verifies it in the bridge, captures the statement account's exact message in the virtual OS on live Sepolia state, and proves the large proof.

| Stage (Sepolia, 23 September 2026) | Result |
| --- | --- |
| Deployment and four deposits | On chain; commitments equal the wallet's |
| Client proof, from on-chain events | 4.7 s, 0.30 GiB peak RSS |
| Virtual OS on live state | 11.8 s, exact message |
| Large proof | 118.8 s, 250,814 bytes, verified |
| Signed relayer transfer, simulated with validation | Succeeds: the adapter checks the real facts and the pool applies the spend against the live root |
| Gateway | Rejects the large proof's proof version (`PROOF_VERSION_NOT_ALLOWED`); stateless, no fee |

From a relayer account with a Sierra 1.7 class, the simulated transfer costs about 135M L2 gas (3.1 test STRK), of which `apply_spend` is 52.2M and about 75M is the per-proof charge. Older account classes (below Sierra 1.7) make Starknet bill the pool's hashing by Cairo steps, about 2.7× more. Evidence is in `bench/m31-sepolia/`.

## Open notes

The R0 client proof binds a public execution intent and an optional identity handle. The M31 pool's `apply_spend_with_invoke` settles `INVOKE` (Ekubo- and Vesu-style anonymizers) and `COMPUTE` (upstream's shadow-account anonymizer, restricted to owner-allowed classes).

**Local end to end with real proofs:**

| Stage | Result |
| --- | --- |
| Client proof | 2.0 s, 0.31 GiB |
| Bridge | 19/19 cases, 1.99M steps |
| Virtual OS | 3.34M steps, exact message |
| Large proof | 119.6 s, 253,430 bytes, 52.1 GiB |
| Settlement | passes in snforge with the real proof facts |

One output plus one funded open note costs 62.3M L2 gas in the pool call.

**Review.** Three independent reviews (relation math, statement binding, pool contract) found that a public nonce on the public identity handle let anyone enumerate a user's shadow accounts. The nonce is now fixed at zero, and accounts are separated by a private scope. The pool rejects malformed destinations before any external effect, and `COMPUTE` targets must be allowed classes. 32 adversarial open-note tests pass: 12 from the contract review and 20 new, including the target allowlist. A re-review of the fixes is pending.

**Sepolia (2026-09-24):**
- The deposits are on chain.
- The proof-carrying swap of 300 A through upstream's unchanged Ekubo anonymizer and the live Ekubo router, into an open note of 299 B, succeeds when the exact signed transaction is simulated against live state: 150.3M L2 gas, 3.80 STRK.
- The gateway still rejects the large proof (`PROOF_VERSION_NOT_ALLOWED`).
- Evidence is in `bench/m31-sepolia/results/v3-open-note/`.

A shadow-account end to end with upstream's anonymizer has not been run.

## Policy notes

The design (`docs/policy-note-spec.md`) was reviewed independently before implementation: three revisions, ending with GO from both the math and protocol reviews. The implementation adds the P1 relation, its bridge and account, `apply_policy_spend`, the reference escrow and the wallet's seed-recoverable backup.

**Tests:**
- P1 relation: 7 tests, covering the native reference, tampered witnesses, the refund-slot rules and finalization.
- P1 bridge on a real proof: 32/32 cases, including every altered statement field and an R0 proof.
- Pool: 181 tests, of which 79 are policy tests. They cover decoy notes on another escrow, unset approvals, controller revert, re-entry and wrong return, rollback of a failed callback, and replay.

**Local end to end with real proofs** (`bench/m31-pool/policy_e2e.py`):
1. A depositor creates two escrow notes by deposit.
2. An executor holding only one note's opening proves the arbiter-approved release.
3. The depositor recovers the other note from the seed alone and proves its refund after the deadline.
4. Both settle through the P1 verifier adapter, and the pool's tree ends at the root the beneficiary's wallet computed.
5. The beneficiary finds its notes by trial decryption and proves an ordinary spend of them.

| | Release | Refund |
| --- | ---: | ---: |
| Client proof | 5.3 s, 0.31 GiB | 1.9 s, 0.30 GiB |
| Bridge | 2.02M steps | 1.96M steps |
| Virtual OS | 3.41M steps | 3.33M steps |
| Large proof | 111.0 s, 50.9 GiB | 110.8 s, 51.7 GiB |
| `apply_policy_spend` | 52.4M L2 gas | 51.5M L2 gas |

The implementation review found no blocking issue in the relation or the contracts; its wallet and defense-in-depth findings are addressed, and both reviewers' tests (33 contract and 11 malicious-witness) are in the repository. The wallet's derivations and encodings are pinned by known-answer vectors.

**Still open:**
- a real-proof settlement of a split outcome;
- private creation through an ordinary output, end to end;
- Sepolia, which is blocked on large-proof acceptance at the gateway;
- a production wallet key scheme: the end to end uses fixture spending and incoming keys.

## Wrapping server

The large-proof flow's smallest leaf is a Cairo trace of 2²⁵ rows, so each wrap costs about two minutes of server time. Bounded-memory storage keeps commitment trees as coefficients, rebuilds them for openings and runs FRI in batches. Proofs stay byte-identical and verify.

| Server storage (policy-note PIE, four cores, zero swap) | Peak RSS | Prove time | Hard cap |
| --- | ---: | ---: | --- |
| Full storage (reference) | 51.7 GiB | 111–118 s | — |
| Bounded, whole trees (**default**) | 27.8 GiB | 122–128 s | passes 30 GiB |
| Bounded, streamed commitments (opt-in) | 22.0 GiB | 148 s | passes 24 GiB |

The server receives the client proof and its public statement only. It must be built with native CPU features for these times. Evidence is in `bench/m31-private-wrapper/proof2-large/`.

## Client proof and privacy

The client proofs are blinded stwo-circuits proofs in an arithmetic-only component profile: no lookup tables, so range checks use bits and no lookup multiplicities can leak. Their zero-knowledge argument is still being qualified: one hiding issue was found and fixed in Templar's prover build, and the full argument has not been independently confirmed. Real value is gated on it.

## How this design was reached

- **Custom compact proof.** A purpose-built M31 membership proof ran natively in 1.17–1.20 s at 63–64 MiB, and in a Chrome WASM worker in 1.89–2.12 s at about 80 MiB of linear memory (`bench/m31-private-e2e/`).
- **Public-path experiments.** felt252 Poseidon membership and M31 trees, natively and in WASM, showed that felt252 lookup tables dominate client memory and that M31-native arithmetic is the lever (`bench/poseidon-membership/`, `bench/wasm-membership/`, `bench/m31-tree/`).
- **Wrapping into a small proof** hit the small-proof flow's 2²⁰-row limit per component and exhausted a 96 GiB server. Starknet v0.14.4's large-proof flow removed the ceiling: the first wrapped bridge proved in 138 s at 61 GiB (`bench/m31-private-wrapper/`).
- **Standard blinded proofs.** Rewriting the relation for stwo-circuits in an arithmetic-only profile removed the custom verifier circuit and the unused lookup tables, putting client, bridge and large-proof wrapping on one code line.
- **Full client-side proving came first.** An earlier pool with a felt252 note format proved whole Cairo spends on the device as small proofs. It ran complete lifecycles on Sepolia (offline push payments, viewing, seed recovery, recovered-note spends, withdrawals and an Ekubo swap into a private note) at about 19–20 s and 14 GiB per proof, or 23 s within 8 GiB with bounded memory. That is too heavy for phones and browsers, so it is no longer maintained; a device-side path on the M31 pool is [future work](/architecture/proving#future-a-faster-device-side-path). Its records are in `bench/push-e2e/`, `bench/controlled-push-e2e/`, `bench/return-note-e2e/` and `bench/bounded-memory/`.

## Recovery and synchronization

The reference scanner, built for the earlier full client-side pool, pins one accepted block and requires agreement between two RPC providers on the block, pool class, root, count, indexed commitments/delivery digests, and candidate-nullifier flags. It rebuilds the root, verifies payloads, and rechecks canonical block identity after the scan.

Both providers are trusted for state authenticity. This is not consensus verification or a state-proof light client. Colluding providers could lie. Candidate-nullifier queries reveal wallet access patterns to the providers, so private spent-status synchronization still needs work.

Five fresh watch/restore scans over only 6–8 notes took approximately **16.5–31.5 seconds**, despite carrying only 1,824–2,432 ciphertext bytes. Per-position RPC reads dominate this small reference implementation. These results do not establish scalable history synchronization.

Missing payloads produce incomplete results rather than complete zero balances. Corruption and omission drills use real downloaded history. Reorg handling is covered by fixtures, not forced Sepolia reorganizations. Balances are explicitly as of the checkpoint; L2 acceptance is not irreversible L1 finality.

## Current configuration boundary

Each relation has its own adapter, pinned to the large-proof format, the virtual OS program, its statement account and class, and its account tag. The experimental maximum proof age is **4,096 blocks**, separate from the **256-root** pool history. The owner can change the R0 and P1 verifiers and the shadow-anonymizer allowlist. No pool fee is charged.

Submission uses sncast signing and the official Sepolia gateway for proof-bearing transactions, with explicit fee bounds. Proof-aware estimation and proof preservation through the intended wallet/RPC path remain unqualified.
