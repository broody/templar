# Code map

Paths are relative to the repository root. They identify source responsibilities rather than
installation steps; the repository README has the commands to build and test them. The primary
packages under `packages/` have not yet adopted these formats.

## A useful reading order

For the split architecture, start with `payment.rs` for the note and spend rules, read the R0
bridge next to it to see how the public statement is decoded and bound, then `pool.cairo` and
`adapter.cairo` for settlement, and `policy_e2e.py` for a complete run. For full client-side
proving, start with `protocol.py`, then `spend.cairo` with `statement.cairo`, then `pool.cairo`,
`proof_adapter.cairo` and `sync.py`.

A check made only by a client is not a pool invariant. A valid proof matters only if the adapter
selects the intended statement and the pool applies exactly its bound operation. A recovery result
also depends on complete encrypted history and a trustworthy canonical checkpoint.
