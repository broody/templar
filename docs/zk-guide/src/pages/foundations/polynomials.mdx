# Polynomials

## Two ways to describe a polynomial

Over a field (Part 1.1), a polynomial like `f(x) = x² + 3` can be written two
ways, and the tension between them is the whole of Part 3 of this course:

- **Coefficients**: `(1, 0, 3)` — how it is *stored* and multiplied.
- **Values**: its outputs at chosen input points — how it is *checked*.

A polynomial of degree `d` is fully determined by `d+1` value points, and —
the key fact — a nonzero polynomial of degree `d` has **at most `d` roots**
(input points where it equals zero).

> **Check.** Plot `f(x) = (x−1)(x−2)(x−3) mod 7` over `x = 0…6`. It is zero
> exactly at 1, 2, 3 — degree 3, exactly 3 roots, never more.

## Interpolation: values determine the polynomial

Given `n` values at `n` distinct points, there is **exactly one** polynomial
of degree `< n` passing through them (Lagrange interpolation). So a table of
numbers and a polynomial are the same object viewed two ways:

```python
P = 2**31 - 1

def interpolate(xs, ys):
    """Unique degree < n polynomial through (xs, ys), mod P."""
    n = len(xs)
    coeffs = [0] * n
    for i, (xi, yi) in enumerate(zip(xs, ys)):
        # build the i-th Lagrange basis polynomial and add it in
        num, den = [1], 1
        for j, xj in enumerate(xs):
            if j != i:
                num = poly_mul_linear(num, xj)   # multiply by (x - xj)
                den = den * (xi - xj) % P
        scale = yi * pow(den, -1, P) % P
        for k, c in enumerate(num):
            coeffs[k] = (coeffs[k] + scale * c) % P
    return coeffs

def poly_mul_linear(poly, x):
    out = [0] * (len(poly) + 1)
    for k, c in enumerate(poly):
        out[k]     = (out[k] + c * (-x)) % P
        out[k + 1] = (out[k + 1] + c) % P
    return out

xs = [1, 2, 3]
print(interpolate(xs, [2, 4, 6]))  # represents f(x) = 2x
```

## The "few unknowns" principle

Here is the principle that makes proofs possible. Suppose someone claims a
huge list of values is "the honest output of some computation", and the
honesty condition is algebraic — some equation must hold relating the values.
Encode the list as a polynomial `f`. Then:

- **If the list is honest**, some expression built from `f` is the zero
  polynomial.
- **If even one value is wrong**, that expression is a nonzero polynomial of
  degree `d` — which has at most `d` roots, so it is nonzero at (almost) every
  random point you might test.

So a verifier who samples the expression at **one random point** catches any
single-value cheat with probability roughly `1 − d/p` where `p ≈ 2¹²⁴` for the
secure field. One random test, overwhelming certainty.

This is called the **Schwartz–Zippel** principle, and it is the reason
proof systems evaluate expressions at random points instead of checking
every row.

> **Check.** Two degree-1 polynomials over F₇ that agree at `x=1` but differ
> elsewhere: `f = x`, `g = 2x − 1`. They agree only at `x = 1` — one point.
> Now make two quadratics agree at 3 points without being equal — you can't.
> That impossibility *is* the principle.

## What "low degree" means downstream

A prover will commit to a huge table by committing to its polynomial. The
verifier cannot see the polynomial — but it can demand *evaluations* at
random points, and it can demand a proof that the committed object really is
a polynomial of the claimed degree (not some arbitrary table that happens to
pass spot checks). That demand is FRI, Part 3.2. Everything before that is
bookkeeping; everything after it is trust.

## What to carry forward

1. Table ↔ polynomial: same object, two views.
2. Degree `d` ⇒ at most `d` roots ⇒ random-point testing catches cheats.
3. "Prove honesty" = "prove a related polynomial is identically zero",
   which random evaluation tests almost for free.
